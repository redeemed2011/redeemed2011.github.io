07./garage-assistant

AI garage operations assistant and build tracker

2026 · garage assistant in Slack, web dashboard, Cloudflare

>_About 50 BDD feature files, each behavior with a passing and a failing case. · Designed to run on Cloudflare's $5-a-month Workers plan.

Mechanics at a vehicle build and repair garage keep posting from their phones as they always have, and every build's record stays complete.

Slack → signed webhook → Cloudflare Worker → queue → AI readers on Workers AI → D1 database and R2 file storage → phone-first web board.

# key decisions

  1. Replaces a spreadsheet, a whiteboard, a retyped daily status doc, and a group text for vehicle builds and repairs. The build crew posts texts, photos, receipts, PDFs, and voice notes in Slack, and the garage assistant files each one to the right build. When the build is unclear or a post looks like a duplicate, it asks instead of guessing.
  2. Several vision models read each receipt in parallel, each field is decided by majority vote, and the arithmetic is checked. Mismatched totals, duplicate invoices, and unusual prices go to a person. Duplicates are caught in any format: a photo, a PDF, and a typed note about the same receipt are compared on what they say.
  3. Every write is idempotent, logged, and undoable, and nothing is hard-deleted. Corrections work in plain words, such as "move the water pump to the other truck", and invoiced records never move. Labor hours are tracked without ever editing invoiced time, and the garage leader gets a daily labor report.
  4. A watchdog resends any post that stalls, then alerts a person. Every deploy runs the full test suite, checks migrations, smoke-tests health, and rolls back on failure. Nightly backups get a monthly restore drill.
  5. Leaders get a phone-first board by build stage, build pages with tasks, parts, receipts, and photos, and a print page. Sign-in is Slack plus a passkey, with role-based permissions.
  • Cloudflare Workers
  • D1
  • R2
  • Queues
  • Workers AI

08./pi-toolbag

pi-toolbag: CTX long-horizon focus and LLM failover for coding agents

2026 · open source · github.com/redeemed2011/pi-toolbag

Coding agents that stay on task for the long haul and keep working when a model provider fails.

Extensions for the Pi coding agent: CTX rebuilds working context after each compaction, and a shared failover library replays failed requests on the next model.

# key decisions

  1. CTX keeps a coding agent focused across context compactions without stopping it from useful exploration. It rebuilds context from typed records within a fixed token budget, with no extra model call.
  2. Project rules are shared across sessions only after an explicit bind that a person confirms, so an agent's passing notes never become rules on their own.
  3. Same-session failover switches on quota, timeout, safety errors, and stalled streams, and never on auth errors or refusals. No user action is needed.
  4. Usage-cap gates switch away before a model hits its limit and switch back once usage recovers.
  • TypeScript
  • Pi coding agent
  • Vitest
  • BDD

11./job-search

AI job-search pipeline

2026 · scheduled agent

>_241 tests pass. · On a test run of one metro area's employers, it kept 48 roles and dropped 326, each with its reason.

Matching roles come straight from employers' own careers sites, each with a company card and scam and ghost-job checks. Mail replies keep each role's status current.

Careers-site job feeds → title and rule filters → scam and ghost checks → status-grouped web page.
SEC, WARN, stock, and news data → company cards.
Weekday mail checks → role status.
Blocked sites → browser agent.

# key decisions

  1. Reads each employer's careers site broadly, then filters by fixed titles and rules. Covers Greenhouse, Lever, Ashby, Workday, Oracle, Phenom, Avature, and SmartRecruiters job feeds, and splits searches that pass Workday's 2,000-result cap.
  2. Sends only sites that block scripts to a browser agent running typesafe.ai's Jev, with spaced, backed-off requests.
  3. Checks mail at 6:30 AM and 4 PM CT each weekday through a read-only mail agent. It reads full threads in Inbox, Sent, Trash, and Spam, so replies update each role's status.
  4. Adds a company card for each employer with a kept role: financial health from SEC filings, layoffs in the last 24 months from SEC and state WARN notices, open-role trend, 12-month stock change against the S&P 500, and up to 3 recent headlines. Free sources only, and every figure carries its date and source.
  5. Labels every role for scam risk and ghost-job risk with fixed rules, not a model's opinion. Eight hard flags, such as a fee up front or a request to run code, mark a likely scam. No label removes a role, and every dropped role shows its reason.
  • Python
  • Careers-site job feeds
  • Read-only mail agent
  • Browser agent
  • SEC and WARN filings
  • Rule-based scam checks

Each model has a specific job, and some jobs have a fallback.
